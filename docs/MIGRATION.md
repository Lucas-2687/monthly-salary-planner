# 从旧站安全迁移

迁移期间保留旧站。不要同时在新旧站持续编辑；它们使用独立数据库，不会自动双向同步。

## 准备

1. 在常用设备打开旧站，等待“已保存到云端”。若有冲突或待同步记录，先处理或单独导出副本。
2. 旧站右上角菜单选择“导出全部计划”，保存原始 JSON 至私有存储；不把备份放进 GitHub。
3. 运行 `npm run backup:verify -- path/to/old.json` 检查格式、月份及记录数量。脚本不会打印金额或备注。
4. 将旧站作为唯一写入入口，先用虚构记录验证新部署。

## 最终切换

1. 暂停旧站写入，导出最终原始备份，并保留不可覆盖的副本。
2. 登录新站，在页脚选择“完整恢复备份”。此操作会先导出新站当前状态，再替换其全部计划、投入、估值和储蓄记录。不要使用普通“导入”进行精确迁移，普通导入会保留新站额外的月份和记录。
3. 等待状态显示“已保存到云端”，刷新并从第二台设备检查。
4. 在新站导出全部计划，运行：

```sh
npm run backup:verify -- path/to/old.json path/to/new.json
```

核对工具按版本 9 规范化旧格式，再比较每个预算项目、定额和百分比、所有投入记录、估值、期初余额与储蓄流水，同时核对收入合计、投入合计和储蓄余额。导出时间、界面当前选中月份不影响比较。任何差异都会返回失败；不要在差异未解释时停用旧站。

5. 对照页面抽查历史月份和区间收益。核对通过后，新站成为唯一写入入口；旧站保留作回退参考。

## 异常与回退

网络异常时保留原始备份和当前浏览器，不强行覆盖云端。新站若已产生新记录，回退前也要导出并核对，不能直接切回旧站造成新数据丢失。

旧站浏览器缓存无法跨域直接读取。仍未同步的旧端数据必须在原域名、原设备上恢复或导出。新站 3 MB 请求上限低于旧版 5 MB；若原始备份超限，先评估大小和内容，不能拆分后盲目覆盖。
